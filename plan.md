# План проекта «Погода OpenWeather»

## Цель

Создать учебное Python-приложение для получения текущей погоды через OpenWeather с двумя интерфейсами на выбор: консольным (CLI) и графическим (GUI на Tkinter). Приложение должно безопасно хранить API-ключ, понятно сообщать об ошибках, кэшировать последний успешный ответ и повторять временно неудачные запросы.

## Этапы реализации

1. **Документация и конфигурация**
   - создать `plan.md` и русскоязычный `README.md`;
   - создать локальный `.env` для ключа и безопасный шаблон `.env.example`;
   - добавить в `.gitignore` секреты, виртуальные окружения, кэш Python и `weather_cache.json`;
   - зафиксировать зависимости `requests` и `python-dotenv` в `requirements.txt`.

2. **Общая логика в `weather_app.py`**
   - загружать ключ через `load_dotenv()` и `os.getenv("API_KEY")`;
   - реализовать `get_coordinates(city: str) -> tuple[float, float]` через OpenWeather Geocoding API с `limit=1` и `lang=ru`;
   - реализовать `get_weather_by_coordinates(lat: float, lon: float) -> dict` через Current Weather API с `units=metric` и `lang=ru`;
   - добавить тайм-аут запросов и до трёх повторов при `429`, `5xx` и сетевых ошибках с паузами 1, 2 и 4 секунды;
   - не повторять постоянные ошибки, включая неверный ключ;
   - обрабатывать отсутствующий или неверный ключ, пустой ответ геокодинга, ошибочные HTTP-статусы, некорректный JSON и сетевую недоступность без трейсбеков;
   - форматировать успешный результат в виде `Погода в <город>: <температура>°C, <описание>`.

3. **Кэширование**
   - сохранять последний успешный ответ в `weather_cache.json` с метаданными `city`, `lat`, `lon`, `fetched_at` и исходными данными погоды;
   - при временной сетевой ошибке предлагать вывести кэш, только если ему меньше 3 часов;
   - явно показывать, что данные взяты из кэша, для какого города и когда сохранены;
   - не подменять кэшем ошибку неверного ключа или ненайденного города;
   - корректно обрабатывать отсутствующий или повреждённый кэш.

4. **CLI**
   - добавить режимы `1 — по городу`, `2 — по координатам`, `0 — выход`;
   - проверять пустой ввод и диапазоны координат;
   - выводить понятные сообщения об ошибках и предупреждения о проблемах с кэшем.

5. **GUI**
   - реализовать окно Tkinter с переключателем режимов «По городу» и «По координатам»;
   - использовать общие функции API, кэша и форматирования;
   - выполнять сетевой запрос в фоновом потоке, чтобы не блокировать окно;
   - показывать состояние загрузки, результат и ошибки;
   - предлагать данные из свежего кэша через диалог при временной сетевой ошибке;
   - при отсутствии ключа показывать подсказку и блокировать запросы.

6. **Выбор интерфейса**
   - добавить `main.py` с меню выбора CLI или GUI;
   - поддержать необязательные флаги `--cli` и `--gui`;
   - обеспечить запуск CLI напрямую через `weather_app.py`, GUI — через `gui.py`;
   - корректно сообщать, если Tkinter недоступен, не мешая запуску CLI.

7. **Проверки**
   - добавить тесты `unittest` с моками для успешных ответов, неверного ключа, пустого геокодинга, повторов, кэша и форматирования;
   - проверить компиляцию всех модулей и импорт GUI;
   - проверить запуск без API-ключа;
   - выполнить реальные запросы к OpenWeather после добавления ключа пользователем;
   - обновить `plan.md` фактическими результатами.

## Фактическое выполнение

- Созданы `.env`, `.env.example`, `.gitignore` и `requirements.txt`. В `.env` добавлен действующий ключ; файл исключён из Git.
- Создано виртуальное окружение `.venv`; установлены `requests 2.34.2` и `python-dotenv 1.2.4` вместе с зависимостями.
- Реализованы `weather_app.py`, `gui.py` и `main.py`.
- API-ключ загружается через `load_dotenv()`; функции геокодинга и текущей погоды используют требуемые параметры, включая `limit=1`, `units=metric` и `lang=ru`.
- Реализованы тайм-аут 10 секунд, три повтора с паузами 1, 2 и 4 секунды для `429`, `500`, `502`, `503`, `504` и сетевых ошибок. Постоянные ошибки не повторяются.
- Реализовано кэширование последнего успешного ответа с метаданными и проверкой возраста в три часа. Кэш предлагается только при временной ошибке.
- Консольный интерфейс поддерживает режимы `1`, `2` и `0`; GUI поддерживает те же режимы через переключатель, выполняет запросы в фоновом потоке и показывает диалог использования кэша.
- `main.py` предлагает выбор интерфейса и поддерживает флаги `--cli` и `--gui`.
- Созданы 18 тестов `unittest` с моками для API, повторов, кэша, валидации и чтения буфера обмена.
- Парсер координат принимает десятичную точку и запятую, знак градуса, пробелы, запятые и точки с запятой в качестве разделителей.
- В GUI координаты вводятся в одно поле, как в CLI. Добавлена кнопка вставки единой строки координат из буфера обмена с проверкой формата.
- В CLI режим координат поддерживает ввод `v` или `в` для вставки строки из буфера обмена и `0` для возврата в меню.
- После успешного запроса GUI показывает дату и время получения данных без секунд в местном часовом поясе рядом со статусом «Данные получены».
- Написаны `README.md` и этот файл.
